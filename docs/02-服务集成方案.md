# 服务集成方案

> 本文档回答：**怎么与现有服务保持打通**。基于对现有 AI 服务的代码探索，给出接口映射、通信选型、统一响应解析、SSE 流式处理实现要点与 Webview 通信架构。

---

## 一、现有服务架构概要

| 维度 | 现状 | 对插件的影响 |
|---|---|---|
| **运行地址** | `http://127.0.0.1:8002`（`run.py` 可配置 `app_host`/`app_port`） | 插件需支持用户配置 base URL |
| **鉴权** | **无任何鉴权**，所有接口匿名可访问 | 插件无需携带 token，简化集成 |
| **CORS** | `allow_origins=["*"]`，完全开放 | Webview 直接请求也不会被拦（但建议走主进程） |
| **响应信封** | 统一 `ApiResponse[T]`：`{"success": bool, "data": ..., "error": ..., "message": ..., ...extra}` | 客户端统一解析逻辑 |
| **SSE 流式** | `/api/agent/invoke/message/stream` 返回 `text/event-stream`，每行 `data: {json}\n\n` | 对话核心体验，需手写流解析 |
| **WebSocket** | `/ws` 端点，EventBus 广播批处理进度等事件 | 本轮对话面板不需要，留作可选扩展 |

源码依据：
- 服务启动与端口：`run.py` -> `uvicorn.run("app.main:app", host=settings.app_host, port=settings.app_port)`
- CORS 配置：`app/main.py` -> `CORSMiddleware(allow_origins=["*"])`
- 响应信封：`app/core/rest/response.py` -> `success()` / `error()`
- Agent 对话路由：`app/api/agent/invoke/views.py`

## 二、通信方式选型

### 2.1 三种通信方式对比

| 方式 | 适用场景 | 服务端支持 | 插件实现复杂度 | 本插件采用 |
|---|---|---|---|---|
| **HTTP REST** | 列表、创建、查询等一次性请求 | 全部接口支持 | 低（Node `http`/`fetch`） | ✅ 列 Agent / 建会话 / 查历史 |
| **SSE 流式** | 服务端逐步推送数据（对话逐字输出） | `/message/stream` 返回 `text/event-stream` | 中（需手写流读取） | ✅ 对话核心 |
| **WebSocket** | 双向实时通信（任务进度推送） | `/ws` 端点 + EventBus | 中 | ❌ 本轮不需要 |

### 2.2 结论

- **对话流程**：建会话 + 查历史用 HTTP；发消息用 **SSE 流式**（`/message/stream`），实现打字机效果。
- **网络层位置**：所有请求在**扩展主进程**（Node.js 环境）执行，Webview 只做渲染。原因：
  1. 主进程可用 Node 原生 `http` 模块，不受浏览器跨域/CORS 限制。
  2. SSE 的 POST + body 请求无法用浏览器 `EventSource`（仅支持 GET），必须用 Node 流式读取。
  3. 集中网络逻辑便于统一错误处理与日志。

| 项 | 内容 |
|---|---|
| **路径** | `POST /api/agent/invoke/session` |
| **请求** | `application/json` Body：`{"agent_id": "<string>"}` |
| **响应** | `ApiResponse[InvokeSessionOut]` -> `data: {"session_id": "<string>", "agent_id": "<string>"}` |

{ "agent_id": "default-assistant" }

```json
{
  "success": true,

  "data": { "session_id": "abc-123-def", "agent_id": "default-assistant" }

```

> 源码：`app/api/agent/invoke/views.py` -> `create_session`

### 3.3 流式发送消息（核心）

| 项 | 内容 |
|---|---|
| **路径** | `POST /api/agent/invoke/message/stream` |
| **请求** | `application/json` Body：`{"session_id": "<string>", "text": "<string>"}` |
| **响应** | `text/event-stream`，每行 `data: {json}\n\n` |

SSE 事件行格式（`data:` 后为单行 JSON）：

```
data: {"type":"content","data":"你好"}

data: {"type":"content","data":"，有什么"}

data: {"type":"content","data":"可以帮你？"}

data: {"type":"end"}
```

**事件类型说明**（基于 `InvokeService.chat_stream` 输出）：

| `type` | 含义 | 处理方式 |
|---|---|---|
| `content` | 文本内容增量 | 累积并实时追加到聊天气泡 |
| `end` | 流结束 | 标记回复完成 |
| 其他（如 `tool`/`token`） | 工具调用/Token 计数等 | 可选展示或忽略 |

> 源码：`app/api/agent/invoke/views.py` -> `send_message_stream` -> `StreamingResponse(media_type="text/event-stream")`，生成器 `sse_generator` 逐行 `yield f"data: {line}\n\n"`

### 3.4 同步发送消息（备用）

| 项 | 内容 |
|---|---|
| **路径** | `POST /api/agent/invoke/message` |
| **请求** | `{"session_id": "<string>", "text": "<string>"}` |
| **响应** | `ApiResponse[InvokeReplyOut]` -> `data: {"session_id": "...", "reply": "...", "role": "assistant"}` |

> 用于不支持流式或需要一次性完整回复的场景。源码：`send_message`

### 3.5 查询历史消息

| 项 | 内容 |
|---|---|
| **路径** | `GET /api/agent/invoke/history` |
| **请求** | Query：`session_id`、`offset`（默认 0）、`limit`（默认 50，上限 500） |
| **响应** | `ApiResponse[list[InvokeMessageOut]]` |

响应 `data` 元素结构：

```json
{
  "id": 1,
  "session_id": "abc-123",
  "role": "user",          // "user" | "assistant"
  "content": "你好",
  "seq": 0,                // 按 seq 升序
  "create_time": "2026-08-01T10:00:00"
}
```

> 源码：`get_history` -> `GET /history`

## 四、统一响应解析规范

所有非流式接口都返回 `ApiResponse` 信封，客户端需统一解析。

### 4.1 解析逻辑

```typescript
interface ApiResponse<T> {
    success: boolean;
    data?: T;
    error?: string;
    message?: string;
    [key: string]: unknown;   // success() 的 extra 字段（如 task_id, count）
}

/**
 * 解析统一响应信封：success 为 false 时抛错，否则返回 data。
 */
function parseResponse<T>(body: ApiResponse<T>): T {
    if (!body.success) {
        throw new Error(body.error ?? body.message ?? '请求失败');
    }
    return body.data as T;
}
```

### 4.2 错误处理约定

- 服务端业务异常 `BasicException` 被全局异常处理器转为 `{"success": False, "error": "<中文描述>"}`。
- 客户端只需检查 `success` 字段：`false` 时取 `error` 展示给用户，`true` 时取 `data`。
- 网络层错误（连接拒绝、超时）单独捕获，提示"无法连接 AI 服务，请检查服务地址与运行状态"。

## 五、SSE 流式处理实现要点（关键章节）

### 5.1 为何不用浏览器 EventSource

浏览器原生 `EventSource` 只支持 **GET 请求**，无法发送 POST body。而服务端 `/message/stream` 要求 `POST` + JSON body：

```
POST /api/agent/invoke/message/stream
Content-Type: application/json

{"session_id": "...", "text": "..."}
```

因此必须用 **Node.js 原生 `http`/`https` 模块**手动发起请求并流式读取响应体。

### 5.2 Node.js 流式读取实现

```typescript
import * as http from 'http';
import * as https from 'https';
import { URL } from 'url';

/** SSE 事件回调 */
interface StreamCallbacks {
    onContent: (text: string) => void;   // 收到 content 增量
    onEnd: () => void;                    // 流结束
    onError: (err: Error) => void;        // 错误
}

/**
 * 流式发送消息：POST 请求 + 逐行解析 SSE。
 *
 * @param baseUrl  服务地址，如 http://127.0.0.1:8002
 * @param body     请求体 { session_id, text }
 * @param cbs      事件回调
 * @returns AbortController（可用于中断）
 */
function streamMessage(
    baseUrl: string,
    body: { session_id: string; text: string },
    cbs: StreamCallbacks
): AbortController {
    const controller = new AbortController();
    const url = new URL('/api/agent/invoke/message/stream', baseUrl);
    const lib = url.protocol === 'https:' ? https : http;
    const payload = JSON.stringify(body);

    const req = lib.request(
        {
            hostname: url.hostname,
            port: url.port,
            path: url.pathname,
            method: 'POST',
            headers: {
                'Content-Type': 'application/json',
                'Content-Length': Buffer.byteLength(payload),
                'Accept': 'text/event-stream',
            },
            signal: controller.signal,
        },
        (res) => {
            if (res.statusCode !== 200) {
                cbs.onError(new Error(`服务返回状态码 ${res.statusCode}`));
                return;
            }

            let buffer = '';
            res.setEncoding('utf-8');
            // 逐块读取，按双换行分割 SSE 事件
            res.on('data', (chunk: string) => {
                buffer += chunk;
                // SSE 事件以 \n\n 分隔
                let idx: number;
                while ((idx = buffer.indexOf('\n\n')) >= 0) {
                    const eventBlock = buffer.slice(0, idx);
                    buffer = buffer.slice(idx + 2);
                    handleSseLine(eventBlock, cbs);
                }
            });
            res.on('end', () => {
                // 处理缓冲区剩余
                if (buffer.trim()) {
                    handleSseLine(buffer, cbs);
                }
                cbs.onEnd();
            });
        }
    );

    req.on('error', (err) => {
        if (err.name !== 'AbortError') {
            cbs.onError(err);
        }
    });
    req.write(payload);
    req.end();

    return controller;
}

/** 解析单个 SSE 事件块（形如 `data: {...}`）。 */
function handleSseLine(block: string, cbs: StreamCallbacks): void {
    // 取 data: 开头的行
    for (const line of block.split('\n')) {
        const trimmed = line.trim();
        if (!trimmed.startsWith('data:')) {
            continue;
        }
        const jsonStr = trimmed.slice(5).trim();
        if (!jsonStr) {
            continue;
        }
        try {
            const evt = JSON.parse(jsonStr);
            if (evt.type === 'content' && typeof evt.data === 'string') {
                cbs.onContent(evt.data);
            } else if (evt.type === 'end') {
                cbs.onEnd();
            }
            // 其他类型（tool/token 等）可按需扩展
        } catch {
            // 非 JSON 行，忽略
        }
    }
}
```

### 5.3 关键点总结

| 要点 | 说明 |
|---|---|
| 用 `http.request` 而非 `fetch` | Node `fetch` 消费流稍繁琐；原生 `http` 流式 `data` 事件更直观可控 |
| `signal` 支持中断 | 用户点击"停止生成"时 `controller.abort()`，服务端流被取消 |
| 按 `\n\n` 分割事件 | SSE 规范：事件之间用空行分隔；单个事件内可有多个 `data:` 行 |
| `content` 累积 | 每个 `content` 事件是增量文本，追加到当前回复气泡即可 |
| 错误状态码先判 | 非 200 直接走错误回调，避免把错误页当 SSE 解析 |

## 六、服务地址配置

通过 `package.json` 的 `configuration` 贡献点声明用户可配置项：

```jsonc
"contributes": {
  "configuration": {
    "title": "AI Agent",
    "properties": {
      "aiAgentChat.serviceBaseUrl": {
        "type": "string",
        "default": "http://127.0.0.1:8002",
        "description": "AI 服务的 Base URL（FastAPI 服务地址）",
        "scope": "window"
      }
    }
  }
}
```

在扩展主进程中读取：

```typescript
import * as vscode from 'vscode';

function getServiceBaseUrl(): string {
    const config = vscode.workspace.getConfiguration('aiAgentChat');
    return config.get<string>('serviceBaseUrl', 'http://127.0.0.1:8002');
}
```

用户可在 VSCode Settings 界面搜索 "AI Agent" 修改此值，无需改代码即可切换服务地址。

## 七、Webview ↔ 扩展主进程通信架构

### 7.1 通信协议设计

所有消息均为 `{ command: string, [key: string]: any }` 格式。

**Webview -> 主进程（用户操作）：**

| command | 携带数据 | 主进程动作 |
|---|---|---|
| `requestAgents` | - | 调 `GET /api/agent/config`，返回 Agent 列表 |
| `createSession` | `{ agentId: string }` | 调 `POST /session`，返回 `sessionId` |
| `sendMessage` | `{ sessionId: string, text: string }` | 调 SSE `/message/stream`，逐字回推 |
| `stopStream` | `{}` | abort 当前 SSE 请求 |
| `loadHistory` | `{ sessionId: string }` | 调 `GET /history`，返回消息列表 |

**主进程 -> Webview（推送结果）：**

| command | 携带数据 | Webview 动作 |
|---|---|---|
| `agentsLoaded` | `{ agents: AgentInfo[] }` | 渲染 Agent 下拉选择 |
| `sessionCreated` | `{ sessionId: string }` | 标记会话已建立，启用输入框 |
| `replyChunk` | `{ text: string }` | 追加到当前 assistant 气泡（打字机效果） |
| `replyEnd` | `{}` | 标记回复完成 |
| `historyLoaded` | `{ messages: Message[] }` | 渲染历史消息列表 |
| `error` | `{ message: string }` | 弹出错误提示 |

### 7.2 主进程处理示例

```typescript
panel.webview.onDidReceiveMessage(
    async (msg: { command: string; [k: string]: unknown }) => {
        switch (msg.command) {
            case 'sendMessage': {
                const controller = streamMessage(
                    getServiceBaseUrl(),
                    { session_id: msg.sessionId as string, text: msg.text as string },
                    {
                        onContent: (text) => panel.webview.postMessage({ command: 'replyChunk', text }),
                        onEnd: () => panel.webview.postMessage({ command: 'replyEnd' }),
                        onError: (err) => panel.webview.postMessage({ command: 'error', message: err.message }),
                    }
                );
                // 保存 controller 供 stopStream 中断
                activeControllers.set(msg.sessionId as string, controller);
                break;
            }
            case 'stopStream': {
                activeControllers.get(msg.sessionId as string)?.abort();
                break;
            }
            // ... 其他 command
        }
    },
    undefined,
    context.subscriptions
);
```

## 八、可选扩展：WebSocket（后续迭代）

服务端 `/ws` 端点已就绪，EventBus 会广播批处理进度、日志等事件。若后续插件要支持"批处理任务监控"，可在主进程用 Node `ws` 模块连接：

```typescript
import WebSocket from 'ws';

const ws = new WebSocket('ws://127.0.0.1:8002/ws');
ws.on('message', (data) => {
    const evt = JSON.parse(data.toString());
    // 按 evt.type 分发到 Webview
    panel.webview.postMessage({ command: 'taskEvent', event: evt });
});
```

本轮对话面板不涉及，仅作预留说明。
