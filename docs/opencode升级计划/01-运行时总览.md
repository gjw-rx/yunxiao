# 运行时总览

## 云效现状

云端 LangGraph 通过本地工具 `interrupt` 暂停，插件 `SessionManager` 收到 SSE `tool_call` 后执行工具并提交结果续流。工具注册、路由、审批与路径守卫已分层，属于可用的混合式雏形。

## OpenCode 做得好

OpenCode 的 `SessionProcessor` 将模型流、推理、工具、step、patch、错误和 usage 纳入一个会话处理器；每一项是会话的一部分，而非临时回调。工具本地执行与 provider 已执行工具也能统一表示。

## 差距

云效的云端与插件各自维护运行状态，没有共同的 run 实体和事件事实来源；插件重载、SSE 断线或服务重启后，无法可靠地继续同一次工作。

## 建议落点与验收

新增 `Run → Step → ToolCall → Event` 追加式模型，云端为事实来源，插件只消费和确认事件。断线后按事件序号重放，重复提交工具结果不得触发第二次模型续流。
