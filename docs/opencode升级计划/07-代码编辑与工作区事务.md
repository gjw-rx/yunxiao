# 代码编辑、Patch 与工作区事务

## 云效现状

`code.edit` 支持精确替换或 unified diff，展示 VSCode diff、审批后 rename 应用，并可接受 `expectedVersion`。当前版本验证发生在审批前，预览期间的外部修改仍可能被覆盖。

## OpenCode 做得好

OpenCode 在每个模型 step 前后跟踪 workspace snapshot，生成 patch Part，并支持 session 级 revert/unrevert。它能回答“本轮改了哪些文件”并把回退限定在明确会话边界。

## 差距

云效有工具级 diff，但没有 run 级变更集合、快照、撤销或审批后的 compare-and-apply；用户无法安全回退一整个 Agent 回合。

## 建议落点与验收

立即在 rename 前重新读取并比较版本，冲突则拒绝。随后引入 run snapshot、patch manifest 和可逆应用；编辑冲突、用户改动、部分失败和 run 回退必须有独立测试。
