# 插件扩展机制

## 云效现状

云端 ToolHookMiddleware 可在工具前后执行 hook，插件端有固定工具注册表。这足以实现内部扩展，但没有统一的第三方插件安装、生命周期、事件契约和故障隔离。

## OpenCode 做得好

OpenCode 从内置、文件和包来源加载插件，初始化 hooks、等待依赖，并将加载失败发布为会话错误而不是击穿整个运行时。插件可以响应 event、环境和工具相关 hooks。

## 差距

云效无法安全地将新的 provider、工具转换、审计器或 UI 行为作为独立包接入；业务修改会不断侵入核心 harness。

## 建议落点与验收

先定义内部插件 SPI：manifest、版本、能力声明、生命周期、hook timeout 和失败隔离。外部安装只在签名、审批、沙箱和供应链策略明确后开放。
