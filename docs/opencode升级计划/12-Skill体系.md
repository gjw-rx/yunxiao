# Skill 体系

## 云效现状

云端已具备 Skill registry、导入、筛选、提示词构造和安全 guard，也支持 Agent 的 skill 白名单。这是已有资产，不应重做。

## OpenCode 做得好

OpenCode 将 skill 作为工具按需加载：模型先看到可用 skill 名称，再调用受权限控制的 `skill` 工具获得正文、基目录和文件清单，避免把所有技能预先注入上下文。

## 差距

云效 Skill 更偏配置/服务能力，缺少按需加载时的会话记录、路径归属、版本 hash 与最小权限语义；技能内容进入上下文后的来源也不够可追溯。

## 建议落点与验收

把 Skill 暴露为显式工具调用，返回名称、版本、来源、内容预算和可访问文件根。加载记录写入 run event；技能变化后旧会话仍可定位到使用过的版本。
