# 权限、审批与能力策略

## 云效现状

路径守卫能阻止 traversal、符号链接越界并识别敏感路径；工具路由按 read/write/execute/destructive 审批。`alwaysAllowTools` 仍是按工具名、跨 session 的长期放行。

## OpenCode 做得好

OpenCode 用 Agent ruleset、工具 permission pattern 和询问流程组合授权；子 Agent 从父规则导出更小权限。shell 对外部目录和命令模式可分别授权。

## 差距

同意一次 `code.edit` 可能过宽地放行同一工具的所有路径；终端授权也不能表达“仅该仓库、仅这个命令模式、仅本次会话”。

## 建议落点与验收

将授权记录为 workspace identity、capability、规范化资源模式、命令模式、过期时间和策略版本。云端只能建议策略，插件必须本地强制；跨工作区、敏感路径、动态命令和过期 grant 均不得复用。
