# 模型提供商与传输韧性

## 云效现状

云端有 LLM builder、模型配置和网关限流；LangChain 统一了多数调用。但模型特定的重试原因、流式 transport 降级、usage/cost 的统一记录仍未成为插件到云端的统一运行合同。

## OpenCode 做得好

OpenCode 将 provider/model capability、请求参数转换、stream event 标准化、provider-executed tool 和 usage/cost 统一处理。它按 5xx、限流、上下文溢出与 `Retry-After` 区分恢复策略。

## 差距

云效难以向 UI 和 trace 明确解释“模型为什么停止、是否会重试、何时可重试、用了多少成本”；不同供应商的细节容易泄露到业务层。

## 建议落点与验收

定义 provider adapter 输出：规范错误分类、retry hint、usage、cost、模型 capability 和 stream completion reason。每种失败都能在 run timeline 中看到且不会把不可重试的上下文溢出误重试。
