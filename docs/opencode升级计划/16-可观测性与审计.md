# 可观测性、成本与审计

## 云效现状

云端已有 Trace middleware 和工具 trace，插件有 ReliabilityMetrics、安全审计和 OutputChannel 日志。这些数据分散在两端，尚不能以同一 run 关联并回放。

## OpenCode 做得好

OpenCode 记录 Part 时间、tool metadata、provider metadata、token、cost、snapshot 和 patch；运行出错时仍保留中间状态，使失败可解释。

## 差距

当前无法从一次用户请求统一回答：调用了哪个模型、用了多少 token、读取了哪些文件、审批了什么、改了哪些文件、为何停止，以及是否可安全重试。

## 建议落点与验收

统一 correlation id 为 run_id，所有云端 trace、插件 tool audit、审批、artifact、patch 和 provider usage 均关联它。建立最小审计视图与脱敏规则，确保敏感参数和内容不写入普通日志。
