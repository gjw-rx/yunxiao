# 会话与事件模型

## 云效现状

插件事件总线包含 content、thought、plan、progress、tool_state_change 与 stream_end；云端以 LangGraph thread 和业务历史保存会话。事件未携带统一运行标识、严格序号或持久状态转换。

## OpenCode 做得好

OpenCode 为工具输入、运行、完成、失败、reasoning delta、step start/finish 分别创建可更新 Part，并保留 provider metadata、时间和 token/cost。UI 不需要猜测工具是否结束。

## 差距

当前事件是展示消息，尚不是可审计协议。乱序、重放、断线重连和“同一工具状态更新两次”缺乏协议级判断依据。

## 建议落点与验收

SSE 增加可选 `protocol_version`、`run_id`、`sequence`、`step_id` 和终态时间；旧事件继续可用。每个状态机迁移都可验证，客户端按 sequence 去重并可恢复时间线。
