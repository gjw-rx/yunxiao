# 实施优先级与依赖关系

## P0：先让基础安全且可验证

1. 修复 TypeScript 编译范围，排除 vendored OpenCode，恢复完整测试门禁。
2. 修复 `code.edit` 审批后的版本复核，阻止 stale preview 覆盖用户修改。
3. 为云端 session agent 与工具幂等记录增加容量、TTL 和持久恢复入口。

## P1：形成可治理 harness

1. 引入 Run/Step/ToolCall/Event、sequence 与结果幂等。
2. 引入工具循环、时间、输出/token 预算和重复调用检测。
3. 引入版本化范围读取、搜索/终端 artifact 和 run 级 patch。
4. 迁移为范围化、本地强制的能力授权。

## P2：形成可扩展产品能力

1. 只读 Explore 子 Agent 与持久 Todo/Question/Plan。
2. MCP 只读连接、资源发现与 trace。
3. 内部插件 SPI、provider adapter 和 UI runtime timeline。

## 验收原则

每一项都必须有单元测试、跨端契约测试及至少一个真实 VSCode E2E；大仓库、网络中断、服务重启、敏感路径和用户并发编辑是不可省略的场景。
