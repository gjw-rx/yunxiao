## Phase 3: Agent Loop (`src/agent/`)

### 任务 3.1: 实现 Agent Loop 核心

- [ ] 创建 `src/agent/agentLoop.ts`
- [ ] 实现 `AgentLoop` 类：
  - [ ] `constructor(provider, messageStore, toolRouter, eventBus, config)`
  - [ ] `async run(sessionId, userText)`: 主循环入口
- [ ] 实现主循环逻辑：
  1. 追加 user 消息到 MessageStore
  2. 进入 while(true) 循环：
     - [ ] 加载历史（historyLoader）
     - [ ] 构建系统提示词（systemPrompt builder）
     - [ ] 物化工具定义（toolRegistry.list -> ToolDefinition[]）
     - [ ] 检查 Max Steps（达到限制时 toolChoice: "none" + 追加提示）
     - [ ] 检查是否需要上下文压缩
     - [ ] 调用 `provider.chatCompletion(request)`
     - [ ] 流式处理 LLMEvent：
       - [ ] textDelta -> EventBus.emit("content", { text })
       - [ ] toolCall -> 收集到 pendingToolCalls
       - [ ] usage -> EventBus.emit("token_usage")
       - [ ] finish -> 判断是否有工具调用
     - [ ] 有工具调用：
       - [ ] 追加 assistant 消息（含 toolCalls）到 MessageStore
       - [ ] 经 ToolRouter 执行每个工具调用
       - [ ] 追加 tool 消息到 MessageStore
       - [ ] step++，continue
     - [ ] 无工具调用：
       - [ ] 追加 assistant 消息到 MessageStore
       - [ ] break
  3. EventBus.emit("stream_end")

- **验证**: 能完成完整的"消息->LLM->工具->续轮->回复"循环
- **参考**: opencode `packages/core/src/session/runner/index.ts`

- [ ] 在 AgentLoop 中添加 `AbortController`

- [ ] 中断后追加 assistant 消息标记为 interrupted
- [ ] 通过 EventBus 发出中断事件

- **验证**: 能正确中断正在执行的 Agent Loop

## 风险与注意事项

1. **API Key 安全**：API Key 存储在 VSCode 配置中，需注意不要泄露到日志或错误报告
2. **流式响应中断**：网络不稳定时流式响应可能中断，需要处理重连或优雅降级
3. **Token 估算精度**：简单字符数/4 的估算不够精确，但足够用于触发判断
4. **工具格式兼容**：确保 ToolDefinition 转换为 OpenAI function calling 格式时无信息丢失
5. **消息顺序**：tool 消息必须紧跟在 assistant 消息之后，注意并发执行后的顺序
6. **compaction 幂等**：确保压缩不会重复执行，compaction 消息只创建一次
7. **前端兼容**：尽量保持 EventBus 事件类型不变，减少前端改动量
