# 重构总体方案

## 一、重构目标

将当前"云端 Agent + 插件端工具"架构改造为"本地全栈 Agent"架构，参考 opencode 的设计理念，但保持 VSCode 插件的轻量级特性。

### 核心目标

1. **去除云端依赖**：移除全部 LangGraph 服务对接代码，Agent 逻辑完全本地化
2. **统一模型连接**：对接所有 OpenAI 规范的模型（含 DeepSeek、通义千问等兼容服务）
3. **本地 Agent Loop**：参考 opencode 实现工具调用循环
4. **上下文压缩**：参考 opencode 锚定摘要策略
5. **Skill 系统**：支持 Markdown 格式的 Skill 动态加载
6. **保留安全优势**：复用已有的路径守卫、安全审计、审批网关

### 非目标（明确不做）

- 不引入 Effect / Effect Schema（保持纯 TypeScript）
- 不引入 SQLite（使用 VSCode 原生存储）
- 不实现 Location-scoped 隔离（单工作区即可）
- 不实现事件溯源（简化为消息列表存储）
- 不实现 steer/queue 投递机制（单轮对话即可）
- 不实现 Plugin Host 变换机制（Skill 系统足够）

## 三、模块设计

### 3.1 模型连接层 (`src/llm/`)

参考 opencode 的 Route 四轴分解，但简化为单文件 Provider 抽象：

```typescript
// 核心接口
interface LLMProvider {
  chatCompletion(request: LLMRequest): AsyncGenerator<LLMEvent>;
}

// LLMRequest
interface LLMRequest {
  model: string;
  messages: LLMMessage[];
  tools?: ToolDefinition[];
  toolChoice?: "auto" | "none" | "required";
  temperature?: number;
  maxTokens?: number;
  stream: true;  // 强制流式
}

// LLMEvent (流式事件)
type LLMEvent =
  | { type: "textDelta"; text: string }
  | { type: "toolCall"; id: string; name: string; arguments: string }
  | { type: "usage"; inputTokens: number; outputTokens: number }
  | { type: "finish"; reason: "stop" | "tool_use" | "length" }
  | { type: "error"; error: string };
```

**设计决策**：

- 统一走 OpenAI `/v1/chat/completions` 接口规范
- 流式解析：手动解析 SSE `data:` 行
- 工具调用：解析 `choices[0].delta.tool_calls`
- 认证：Bearer Token（API Key）
- baseURL 可配置，支持任意 OpenAI 兼容服务

### 3.2 Agent Loop (`src/agent/`)

参考 opencode 双层循环，简化为单层 + 工具续轮：

```
sendMessage(text):
  1. 构建 user 消息，存入 MessageStore
  2. 进入 Agent Loop:
     while (true):
       a. 加载历史消息（含 compaction 检查点）
       b. 构建系统提示词（agent prompt + skill guidance + env info）
       c. 物化工具定义（按权限过滤）
       d. 检查是否需要上下文压缩
       e. 调用 LLM provider.chatCompletion(request)
       f. 流式处理事件:
          - textDelta -> EventBus.emit("content")
          - toolCall -> 收集工具调用
          - finish -> 判断是否有工具调用
       g. 如果有工具调用:
          - 执行工具（经 ToolRouter）
          - 将工具结果存入 MessageStore
          - continue (续轮)
       h. 如果无工具调用:
          - break (轮次完成)
  3. 发出 stream_end 事件
```

**Max Steps 限制**：

- 默认 50 步（可配置）
- 达到限制时：`toolChoice: "none"` + 追加 MAX_STEPS_PROMPT

### 3.3 上下文压缩 (`src/agent/compaction.ts`)

参考 opencode 锚定摘要策略：

```
compactIfNeeded(messages, model):
  1. 估算当前消息总 token 数
  2. 如果 token 数 > (model.contextWindow - maxOutput - buffer):
     a. 分割消息：head（旧，将摘要）+ recent（新，保留原文）
        - 预算：recent 保留 8000 tokens
     b. 生成摘要（调用 LLM，使用结构化模板）:
        ## Objective
        ## Important Details  
        ## Work State (Completed/Active/Blocked)
        ## Next Move
        ## Relevant Files
     c. 存储 compaction 消息（summary + recent context）
     d. 后续历史加载从 compaction 检查点开始
```

**摘要模板**（参考 opencode）：

```markdown
You are maintaining a conversation summary. Create or update an anchored summary.

## Objective
- [用户的核心目标]

## Important Details
- [约束、决策、关键事实]

## Work State
### Completed
- [已完成的工作]
### Active  
- [正在进行的工作]
### Blocked
- [被阻塞的工作]

## Next Move
1. [下一步计划]

## Relevant Files
- [涉及的关键文件]
```

### 3.4 短期记忆管理 (`src/memory/`)

```typescript
// 消息类型
type Message =
  | { role: "system"; content: string; seq: number }
  | { role: "user"; content: string; seq: number; attachments?: Attachment[] }
  | { role: "assistant"; content: string; toolCalls?: ToolCall[]; seq: number }
  | { role: "tool"; toolCallId: string; content: string; seq: number }
  | { role: "compaction"; summary: string; recentContext: Message[]; seq: number };

// MessageStore 接口
interface MessageStore {
  append(sessionId: string, message: Message): void;
  loadHistory(sessionId: string): Message[];
  getCompactionPoint(sessionId: string): Message | null;
  clear(sessionId: string): void;
}
```

**存储方案**：

- 内存存储（主）：Map<sessionId, Message[]>
- 持久化（辅）：VSCode workspaceState（序列化消息列表）
- 限制：每个 session 最多保留 1000 条消息

### 3.5 Skill 系统 (`src/skill/`)

```typescript
// Skill 定义
interface Skill {
  name: string;
  description: string;
  slash?: boolean;  // 是否支持 / 命令触发
  content: string;  // Markdown 正文
  sourcePath?: string;  // 来源文件路径
}

// Skill 源
type SkillSource =
  | { type: "directory"; path: string }  // 本地目录
  | { type: "embedded"; skill: Skill };  // 内联定义

// Skill 格式 (Markdown + frontmatter)
// ---
// name: my-skill
// description: 描述何时使用此 skill
// slash: true
// ---
// Skill 指令内容...
```

**加载流程**：

1. 扫描配置的 Skill 目录（默认 `.vscode/skills/`）
2. 解析每个 `*.md` 文件的 frontmatter + 正文
3. 注册到 SkillRegistry
4. 构建系统提示词时注入可用 Skill 列表
5. LLM 可通过 `skill` 工具主动加载 Skill 内容

### 3.6 系统提示词 (`src/agent/systemPrompt.ts`)

参考 opencode 的可组合 SystemContext，简化为函数式拼接：

```typescript
function buildSystemPrompt(context: {
  agentPrompt?: string;      // Agent 级提示词
  skills: Skill[];           // 可用 Skill 列表
  workspaceRoot: string;     // 工作区根目录
  platform: string;          // 操作系统
  date: string;              // 当前日期
}): string {
  return [
    context.agentPrompt ?? DEFAULT_AGENT_PROMPT,
    buildEnvironmentSection(context),
    buildSkillGuidance(context.skills),
  ].filter(Boolean).join("\n\n");
}
```

**默认 Agent 系统提示词**（参考 opencode build agent）：

```
You are an AI coding assistant integrated into VSCode. You help users with 
software engineering tasks by understanding their codebase, making changes, 
and running commands.

## Environment
- Working directory: {workspaceRoot}
- Platform: {platform}
- Date: {date}

## Capabilities
You have access to tools for:
- File operations (read, write, edit, search, list, delete, move)
- Code intelligence (diagnostics, symbols, references, definitions)  
- Terminal execution
- Git operations
- Skill loading

## Guidelines
- Always read files before editing them
- Make surgical changes - touch only what's necessary
- Use tools to verify your changes (diagnostics, tests)
- Explain what you're doing and why
- If unsure, ask for clarification

{skill_guidance}
```

## 四、改造阶段规划

### Phase 0: 准备工作

- 确认改造范围，备份关键文件
- 新建目录结构

### Phase 1: 模型连接层

- 实现 LLMProvider 接口
- 实现 OpenAI 兼容 Provider
- 实现流式 SSE 解析
- 实现模型配置管理
- 验证：能通过配置的 API Key 调通 LLM 并获取流式响应

### Phase 2: 记忆管理

- 定义消息类型
- 实现 MessageStore
- 实现历史加载（含 compaction 检查点）
- 验证：能存储和加载对话历史

### Phase 3: Agent Loop

- 实现 Agent Loop 核心循环
- 集成 LLM Provider + MessageStore + ToolRouter
- 实现 Max Steps 限制
- 实现中断处理
- 验证：能完成"用户消息 -> LLM 响应 -> 工具调用 -> 续轮 -> 最终回复"完整循环

### Phase 4: 系统提示词 + Skill

- 实现系统提示词构建
- 实现 Skill 加载系统
- 实现 skill 工具
- 验证：Skill 能被正确注入系统提示词并被 LLM 加载

### Phase 5: 上下文压缩

- 实现 token 估算
- 实现锚定摘要压缩
- 实现自动触发 + overflow 恢复
- 验证：长对话能自动压缩且保持上下文连贯

### Phase 6: 去除云端 + 前端适配

- 删除云端相关代码
- 适配 ChatPanel 事件处理
- 适配配置项
- 端到端测试
