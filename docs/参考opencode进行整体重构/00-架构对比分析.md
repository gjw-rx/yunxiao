# 架构对比分析：当前架构 vs opencode 架构

## 一、整体架构对比

### 1.1 当前架构：云端 Agent + 插件端工具

```
┌──────────────────────────────────────────────────────────┐
│                      VSCode 插件端                        │
│                                                          │
│  ┌──────────┐   ┌──────────────┐   ┌──────────────────┐  │
│  │ ChatPanel │   │SessionManager│   │   ToolRouter     │  │
│  │ (Webview) │   │  (状态机)    │   │ (审批+安全+执行)  │  │
│  └────┬─────┘   └──────┬───────┘   └────────┬─────────┘  │
│       │                │                     │            │
│       │          ┌─────┴──────┐        ┌─────┴──────┐     │
│       │          │  AIClient  │        │  本地工具   │     │
│       │          │ (HTTP/SSE) │        │ fs/code/   │     │
│       │          └─────┬──────┘        │ terminal/  │     │
│       │                │               │ git        │     │
│ ┌─────┴────────────────┴───────────────┴────────────┘     │
│ │              EventBus (内部事件总线)                     │
│ └─────────────────────────────────────────────────────────│
└──────────────────────────┬───────────────────────────────┘
                           │ HTTP / SSE
                           ▼
┌──────────────────────────────────────────────────────────┐
│                    云端 LangGraph 服务                    │
│                                                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ Agent    │  │ LLM 推理  │  │ 云端工具  │  │ 历史存储  │  │
│  │ 编排     │->│ (LangChn)│->│ (搜索等) │  │ (会话DB) │  │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘  │
│                                                          │
│  v2 Run API: createRun / subscribeRun(SSE) / toolResult  │
└──────────────────────────────────────────────────────────┘
```

**核心特征**：

- 云端负责 LLM 推理、Agent 编排、会话历史存储、上下文压缩
- 插件端仅负责本地工具执行 + 前端渲染
- 通信协议：v2 Run API（计算与订阅分离，SSE 事件流）
- 模型选择：云端 Agent 配置决定，插件端无感知

### 1.2 opencode 架构：本地全栈 Agent

```
┌──────────────────────────────────────────────────────────┐
│                     opencode 本地                        │
│                                                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │  TUI/Web │  │   CLI    │  │ Desktop  │  │ Client   │  │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └────┬─────┘  │
│       └──────────────┴──────────────┴──────────────┘      │
│                          │                               │
│  ┌───────────────────────┴───────────────────────────────┐│
│  │              Session Runner (Agent Loop)              ││
│  │  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐  ││
│  │  │ 模型解析 │  │ 历史加载 │  │ 工具执行 │  │ 上下文   │  ││
│  │  │ Catalog │->│ History │->│ Tool    │->│ 压缩     │  ││
│  │  └─────────┘  └─────────┘  └─────────┘  └─────────┘  ││
│  └───────────────────────────────────────────────────────┘│
│       │              │              │              │      │
│  ┌────┴────┐  ┌──────┴──────┐  ┌───┴────┐  ┌──────┴────┐  │
│  │ LLM 包  │  │ SQLite(DB)  │  │ Skill  │  │ SystemCtx │  │
│  │ Route   │  │ 事件溯源     │  │ 加载   │  │ 代数      │  │
│  └────┬────┘  └─────────────┘  └────────┘  └───────────┘  │
│       │                                                  │
│  ┌────┴────────────────────────────────────────────────┐  │
│  │  Provider Facades (OpenAI/Anthropic/DeepSeek/...)   │  │
│  └─────────────────────────────────────────────────────┘  │
└──────────────────────────┬───────────────────────────────┘
                           │ HTTPS
                           ▼
┌──────────────────────────────────────────────────────────┐
│              LLM Provider (OpenAI / Anthropic / ...)     │
└──────────────────────────────────────────────────────────┘
```

**核心特征**：

- 全部逻辑在本地，直接对接 LLM Provider
- 模型连接层：四轴正交分解（Protocol/Endpoint/Auth/Framing）
- Agent Loop：双层 while 循环（queue/steer 投递 + 工具续轮）
- 持久化：SQLite + 事件溯源
- 上下文压缩：增量式锚定摘要
- Skill 系统：Markdown + frontmatter，动态加载

## 二、逐模块对比

### 2.1 模型连接层

| 维度     | 当前架构                | opencode                                 | 差距分析                                         |
| -------- | ----------------------- | ---------------------------------------- | ------------------------------------------------ |
| 模型对接 | 云端 LangGraph 服务代理 | 本地直连 LLM Provider                    | **架构不同**：需从"云端代理"改为"本地直连" |
| 模型选择 | 云端 Agent 配置决定     | Catalog 注册表 + 用户选择                | 需新增模型配置和管理                             |
| API 规范 | 无（云端自定义协议）    | 四轴正交分解，支持 OpenAI/Anthropic 兼容 | 需新建模型连接抽象                               |
| 认证     | 无（云端内部通信）      | API Key / OAuth / 自定义 Header          | 需新增认证管理                                   |
| 流式解析 | SSE 事件流（云端封装）  | 原生 SSE/Event-Stream 解析               | 需自建流式解析                                   |

### 2.2 Agent Loop

| 维度        | 当前架构                                           | opencode                            | 差距分析                                    |
| ----------- | -------------------------------------------------- | ----------------------------------- | ------------------------------------------- |
| 循环控制    | 云端 LangGraph 编排                                | 本地双层 while 循环                 | **核心改造**：需在本地实现 Agent Loop |
| 工具续轮    | 云端发起 tool_call -> 插件执行 -> 回传结果 -> 续流 | 本地 runner 直接执行工具 -> 续轮    | 去除 HTTP 往返，改为本地调用                |
| 中断处理    | SSE interrupted 事件                               | interrupt() 标记工具 failed         | 可参考但需适配                              |
| Max Steps   | 无（云端控制）                                     | agent.steps 限制 + MAX_STEPS_PROMPT | 需新增                                      |
| Steer/Queue | 无                                                 | steer（插话引导）+ queue（排队）    | 可选实现                                    |

### 2.3 短期记忆管理

| 维度     | 当前架构                        | opencode                              | 差距分析                     |
| -------- | ------------------------------- | ------------------------------------- | ---------------------------- |
| 历史存储 | 云端会话 DB                     | 本地 SQLite + 事件溯源                | **需新建**：本地持久化 |
| 历史加载 | GET /api/agent/invoke/history   | entriesForRunner（compaction 检查点） | 需新建加载逻辑               |
| 消息格式 | RunEventEnvelope (SSE)          | SessionMessage（类型化 Schema）       | 需重新定义消息模型           |
| 恢复机制 | RunStore（workspaceState 快照） | 事件溯源 replay                       | 可简化参考                   |

### 2.4 工具调用

| 维度     | 当前架构                                       | opencode                                 | 差距分析                                 |
| -------- | ---------------------------------------------- | ---------------------------------------- | ---------------------------------------- |
| 工具定义 | BaseTool 抽象类 + ToolSchema                   | Tool.make (Effect Schema)                | **已有基础**，可保留抽象，调整接口 |
| 工具注册 | ToolRegistry（命名空间注册）                   | ToolRegistry（Location-scoped 栈式注册） | 已有基础，可简化参考                     |
| 工具执行 | ToolRouter（安全+审批+执行）                   | settle（授权+执行+bound）                | **已有优势**：安全机制完善         |
| 工具列表 | fs(6) + code(5) + terminal(1) + git(5) = 17 个 | 12 个内置工具                            | 工具集基本对齐                           |
| 并发执行 | canParallel 判断                               | FiberSet 并发                            | 可参考简化                               |

### 2.5 Skill 加载

| 维度       | 当前架构     | opencode                                  | 差距分析         |
| ---------- | ------------ | ----------------------------------------- | ---------------- |
| Skill 系统 | **无** | 完整 Skill 系统（embedded/directory/url） | **需新建** |
| Skill 格式 | 无           | Markdown + frontmatter                    | 需新建格式规范   |
| Skill 注入 | 无           | SystemContext guidance 注入               | 需新建注入机制   |
| Skill 工具 | 无           | skill 工具（LLM 主动加载）                | 需新增           |

### 2.6 上下文压缩

| 维度          | 当前架构                 | opencode                          | 差距分析                   |
| ------------- | ------------------------ | --------------------------------- | -------------------------- |
| 压缩触发      | 手动 /compact 或云端自动 | 自动（token 预算）+ overflow 恢复 | **需新建**：自动压缩 |
| 压缩策略      | 云端黑盒                 | 增量式锚定摘要（结构化 Markdown） | 需新建摘要策略             |
| 压缩存储      | 云端                     | compaction 类型 SessionMessage    | 需新建存储                 |
| Context Epoch | 无                       | 系统上下文版本管理                | 可选实现                   |

### 2.7 系统提示词

| 维度       | 当前架构        | opencode                              | 差距分析                         |
| ---------- | --------------- | ------------------------------------- | -------------------------------- |
| 提示词来源 | 云端 Agent 配置 | agent.system + SystemContext baseline | **需新建**：本地系统提示词 |
| 上下文注入 | 无              | 可组合 SystemContext 代数             | 需新建上下文注入                 |
| 环境信息   | 无              | 内置 environment/date source          | 需新增                           |

### 2.8 前端渲染

| 维度     | 当前架构                    | opencode                | 差距分析                     |
| -------- | --------------------------- | ----------------------- | ---------------------------- |
| UI 框架  | Webview（内联 HTML/CSS/JS） | TUI (Ink) / Web (React) | **保留**：维持 Webview |
| 消息渲染 | Markdown + 工具时间线       | 类似                    | 已有基础，需适配新事件       |
| 审批 UI  | 内嵌审批卡片                | 权限系统                | **已有优势**：保留     |

### 3.4 技术选型决策

| 决策点        | 选择                               | 理由                                |
| ------------- | ---------------------------------- | ----------------------------------- |
| LLM 调用方式  | 直接 fetch + SSE 解析              | 无需引入 AI SDK 依赖，保持轻量      |
| 持久化方案    | VSCode workspaceState + 内存       | 不引入 SQLite，利用 VSCode 原生能力 |
| Agent Loop    | 参考 opencode 双层循环，简化为单层 | 去掉 steer/queue，保留工具续轮      |
| 上下文压缩    | 参考 opencode 锚定摘要，简化       | 保留结构化模板，去掉 Context Epoch  |
| Skill 格式    | Markdown + frontmatter             | 与 opencode 兼容                    |
| Effect Schema | 不引入                             | 保持纯 TypeScript，降低复杂度       |
| 工具接口      | 保留 BaseTool，调整 execute 签名   | 复用已有安全机制                    |
