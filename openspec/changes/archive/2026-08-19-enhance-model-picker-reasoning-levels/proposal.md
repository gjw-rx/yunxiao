## Why

当前对话输入区的模型切换弹窗只是平铺模型列表，信息层级和选中反馈较弱，也没有把 LLM 层已经具备的推理强度参数暴露给用户。需要将它升级为紧凑、清晰且可访问的会话配置入口，让用户可以在发送前确认模型并选择低、中、高三档推理强度。

## What Changes

- 将输入区现有模型下拉重构为统一的模型配置弹层：首层展示当前模型和当前推理强度，模型行进入已启用模型列表，推理强度行进入低/中/高单选列表，并提供明确的当前项、返回、键盘与关闭反馈。
- 推理强度按模型配置持久化；切换模型时同步展示并应用该模型上次选择的档位。
- 低、中、高分别映射为运行时 `low`、`medium`、`high`，只影响选择完成后启动的新运行，进行中的流式回复继续使用启动时快照。
- 新建模型默认使用中档；已有模型若没有该字段则保持 Provider 原有默认行为，避免升级后无操作即改变请求参数，用户首次选择后再写入显式档位。
- 复用现有 OpenAI-compatible 与 DeepSeek 推理参数适配，不在 Webview 暴露 API Key、baseURL 等敏感连接信息。
- 截图中的“速度”和“高级”入口不属于本次范围，不新增服务等级、文本详细度或其他高级生成参数。

## Capabilities

### New Capabilities

- `reasoning-level-control`: 定义低/中/高推理强度的展示、按模型持久化、运行快照、Provider 参数映射和向后兼容行为。

### Modified Capabilities

- `model-switching`: 将输入区模型切换升级为分层的模型配置弹层，并保持仅展示已启用模型、持久化默认模型和不影响进行中回复等既有契约。

## Impact

- Webview：`MessageInput`、聊天状态 reducer、Host/Webview 协议、输入区弹层样式与组件测试。
- 扩展宿主：`ChatPanelProvider` 的弹层快照与选择消息处理、模型配置存储及旧数据迁移。
- Agent/LLM：`ModelConfig`、`AgentLoop` 动态配置更新，以及现有 AI SDK/legacy Provider 推理参数测试。
- 不引入新的运行时依赖，不更改消息历史、工具调用、审批或 API Key 存储格式。
