## Context

当前实现依赖写工具回调，无法观察 `terminal_exec` 产生的文件修改或 Git 提交。日志中的 OpenSpec 操作经终端完成并提交，因此没有任何工具快照可供统计。

## Goals / Non-Goals

**Goals:**

- 以会话首次运行前的工作区文本快照作为基线。
- 每次最终回复后对比基线与当前工作区，并用同一个会话变更集提供审查。
- 覆盖受控工具、终端命令和 Git 提交造成的工作区文件变化。

**Non-Goals:**

- 不区分某一轮回复或某一条工具调用的归属。
- 不记录 `.git`、依赖目录和超大/非文本文件。

## Decisions

- 持久化会话工作区基线快照，而不是使用 Git diff。这样既能覆盖已提交改动，也能覆盖非 Git 工作区和未跟踪文件。
- Git 工作区使用 `git ls-files` 的已跟踪与未忽略文件清单建立快照，避免递归扫描缓存、依赖和文档镜像；非 Git 工作区才使用带目录排除规则的递归兜底。
- 基线准备与首次模型请求并行；模型真正执行工具前必须等待基线完成，确保不延迟文本回复且不会漏掉工具改动前状态。
- 变更集 ID 固定为 `session`，每次重算覆盖该会话的当前累计结果；历史回复打开的都是当前会话累计视图。
- 复用既有快照文件和摘要格式，避免改变 Webview 协议。

## Risks / Trade-offs

- [大型工作区快照耗时与占用增加] → 跳过依赖、Git、构建目录及单文件过大内容，并记录日志。
- [会话外人工修改也会出现在差异中] → 统计口径明确为会话基线后的当前工作区状态，符合当前 session 的可见变更需求。
