## Context

当前 token 账以 `TokenUsageSnapshot` 挂在 assistant 消息上，由 AgentLoop 写入 MessageStore，再进入工作区会话归档；会话页只对当前活动历史求和。归档 entry 已有 ISO 时间戳，但 token 快照没有实际调用模型，设置页“使用情况”也只有静态占位。

本变更横跨 AgentLoop、消息/归档类型、统计读取、设置 Webview 协议和 React 设置页。统计数据只来自当前工作区的本地归档，不访问 provider 或云端账户。

## Goals / Non-Goals

**Goals:**

- 让每笔新 token 账可稳定归属到实际调用的 provider/模型。
- 按本地自然日、周一开始的自然周、自然月计算当前工作区用量。
- 在设置页展示区间总量和按模型输入、输出、总量及可用细分。
- 保持旧归档可读，对未知模型和局部损坏给出诚实状态。

**Non-Goals:**

- 不计算价格、费用、额度或云端账户用量。
- 不跨工作区汇总，不上传或同步统计数据。
- 不为缺少 tokenUsage 的旧消息生成跨会话估算账。
- 不引入图表库、数据库或后台定时索引。

## Decisions

### 1. 在既有 token 快照中记录不可变模型元数据

扩展 `TokenUsageSnapshot`，记录 `provider_id`、`model_id` 和 `model_label`。AgentLoop 每次 run 已捕获本次模型配置，构造 token 快照时直接使用该配置，确保运行中切换默认模型不会改写归属。统计键使用 `provider_id + model_id`，展示优先使用快照中的 `model_label` 并附 provider，以避免不同 provider 的同名模型混淆。

备选方案是只保存模型配置档案 ID，但档案可能删除或重建，且相同实际模型会被人为拆分；另一个方案是在统计时读取当前默认模型，会错误归属历史调用。因此均不采用。

### 2. 直接扫描追加式会话归档，不维护第二套累计账本

新增职责单一的用量统计服务，通过 `SessionFileStore` 暴露的受控读取能力遍历当前工作区会话归档中的 message entry。每个带 tokenUsage 的 assistant entry 是一笔已经发生的调用；entry 的 `timestamp` 是分桶时间。扫描物理落账记录意味着后来回滚或删除活动消息不会撤销已消耗的 token，也避免从活动 head 丢失真实用量。

备选方案是新建独立 usage ledger 或在 globalState 维护增量汇总。它们查询更快，但会引入双写一致性、迁移和回滚复杂度；当前本地数据规模不足以证明该复杂度必要。

### 3. 宿主负责时间边界和聚合，Webview 只请求明确区间

协议定义 `day | week | month` 粒度和一个参考日期。宿主以本机时区计算 `[start, end)`：天从本地 00:00 开始，周从周一开始，月从第一天开始；响应返回标准化的起止时间、合计、模型行和 `partial` 标记。Webview 不自行扫描历史或重算账目，只负责粒度/前后周期交互与格式化展示，避免 Host/Webview 时区算法分叉。

页面首次进入“使用情况”时请求当前自然日，切换粒度或相邻周期时重新请求。为避免设置页挂载就扫描全部归档，不在页面挂载时预取 usage；只有进入该分类或筛选变化才请求。

### 4. 历史兼容采用“未知模型”，不猜测

旧 token 快照缺少模型元数据时使用固定内部 key `unknown` 和中文标签“未知模型”。缺 tokenUsage 的历史消息在跨会话报表中忽略，因为正文估算既无法还原 provider 权威总量，也无法可靠确定调用时间和模型。单文件解析失败由统计服务记录统一日志并继续扫描，响应 `partial=true`；整体初始化或目录访问失败才通过协议返回错误。

### 5. 使用简单汇总卡和可访问表格

“使用情况”页面使用现有设置页卡片、按钮和 VS Code 主题变量：顶部为日/周/月分段按钮和前后周期导航，中部显示区间与 total/prompt/completion 摘要，下方表格按 total 降序列出模型、输入、输出、总量及可用缓存明细。窄宽度允许横向滚动或将摘要换行，不引入图表依赖。

## Risks / Trade-offs

- [每次请求扫描全部归档，历史很大时可能变慢] → 仅在使用情况分类按需请求；实现时记录归档数、账目数和耗时，并保持统计器接口可在有证据时增加缓存。
- [旧记录集中到“未知模型”，早期模型明细不完整] → 明确显示未知分组，不用当前配置误导性回填。
- [本机时区变化会让同一 UTC 时间落入不同本地桶] → 响应返回实际 `[start, end)`，页面展示区间；这是“自然日/周/月”符合用户直觉的代价。
- [归档损坏导致结果不完整] → 跳过单文件、记录可定位日志并在 UI 显示部分数据提示。
- [追加式归档包含已回滚消息，与当前会话累计口径不同] → 使用情况定义为实际已落账消耗，回滚不撤销 provider 已发生的 token 消耗；页面文案明确数据口径。

## Migration Plan

1. 以可选字段扩展 token 快照和归档解析，旧文件无需重写即可继续加载。
2. 新版本开始为每笔新 token 账写入模型元数据；已有带 tokenUsage 的账在报表中进入“未知模型”。
3. 添加统计服务与协议后再替换使用情况占位，失败时仍可显示错误与重试，不影响其他设置功能。
4. 回滚代码不会破坏旧版本读取：新增 JSON 字段会被忽略；未建立独立索引，无需清理迁移产物。

## Open Questions

无阻塞问题。首版按当前工作区、本机时区、周一为每周起点实施；若未来需要跨工作区或费用统计，应作为独立变更设计数据范围和价格版本化。
