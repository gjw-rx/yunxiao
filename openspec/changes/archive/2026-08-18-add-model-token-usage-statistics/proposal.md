## Why

当前系统只在单个会话内累计 token，用量账目没有保留实际调用模型，也无法按时间范围比较不同模型的消耗。插件设置页已经有“使用情况”入口，但仍是静态占位，用户无法从本地历史判断各模型在日、周、月维度的 token 用量。

## What Changes

- 为新产生的 assistant token 账记录实际调用模型的稳定标识和当时的展示名，避免后续切换、重命名或删除模型配置改变历史归属。
- 从当前工作区持久化会话归档读取 token 账和记录时间，按模型以及自然日、自然周、自然月聚合 token 总量与输入/输出明细。
- 对无法可靠确定模型的旧 token 账归入“未知模型”，不按当前默认模型猜测历史归属。
- 通过设置 Webview 协议按需请求用量快照，并在“使用情况”分类提供日/周/月粒度切换、时间段选择、总量摘要和模型明细表。
- 对空数据、部分历史无模型信息和读取失败提供明确状态；不新增费用或云端账户统计。

## Capabilities

### New Capabilities
- `model-token-usage-reporting`: 定义本地 token 账按模型和自然日/周/月聚合、时间边界、未知模型兼容及统计结果契约。

### Modified Capabilities
- `token-usage-tracking`: token 账新增实际调用模型快照，确保后续能按模型可靠归集。
- `settings-page`: 将“使用情况”静态占位替换为真实的本地模型 token 用量视图。

## Impact

- 影响 token 快照类型、AgentLoop 写账、会话归档读取与统计服务。
- 扩展设置面板新增用量请求/响应协议和消息处理分支。
- React 设置页新增用量状态、筛选控件、汇总与明细展示，并更新对应样式和测试。
- 仅使用现有本地归档，不新增第三方依赖、网络请求或敏感配置暴露；旧归档保持可读。
