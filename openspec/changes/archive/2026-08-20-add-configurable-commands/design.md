## Context

当前斜杠菜单由 `src/chat/slashCommands.ts` 将内置命令与 `SkillRegistry` 内容组装后推送到 Webview；`MessageInput` 对 Skill 使用 chip 引用，对内置命令执行宿主动作或回填文本。设置页已经具备独立 Webview、分类导航和 Host 双向消息通道，但尚无自定义 Command 的持久化、管理和展开链路。

本变更跨越本地文件、扩展宿主、协议与 Webview。Command 被定义为“可复用的提示词模板”，不是终端命令或 VS Code Command，因此加载和发送均不得执行正文中的代码。实现必须遵循项目的中文日志、JSDoc、严格类型及宿主侧路径校验约束。

## Goals / Non-Goals

**Goals:**

- 从用户级与项目级固定目录发现 Markdown Command，并以确定性规则合并。
- 在设置页完成双作用域的查看、创建、编辑、删除和手动刷新。
- 在 `/` 菜单中将“命令”与基础功能、子智能体、Skill 明确分组。
- 让用户选择一个 Command 后继续输入补充说明，并在发送时由宿主安全展开模板正文。
- 通过单元测试、Webview 测试和编译检查验证加载、管理、覆盖、引用及展开行为。

**Non-Goals:**

- 不执行 shell、VS Code API 或 Command 正文内的任意代码。
- 不提供云端 Command、同步、市场、导入导出或目录自定义能力。
- 不实现参数占位符、变量插值、嵌套 Command 或自动监听外部文件变化；首版通过激活、设置操作和手动刷新重载。
- 不改变现有 Skill 文件格式、安装来源或内置基础命令语义。

## Decisions

### 1. 使用单文件 Markdown 格式

每个 Command 存为 `<command-name>.md`。文件可包含扁平 YAML frontmatter：

```markdown
---
description: 审查当前改动并给出风险清单
---
请审查当前改动，按严重级别列出问题，并说明验证建议。
```

命令名取自文件名，正文必须非空，`description` 可选；合法名称限定为小写字母或数字开头，后续仅允许小写字母、数字、`-`、`_`。选择文件名作为唯一标识可避免 frontmatter 名称与实际保存路径不一致。相比复用 Skill 的 `name/description` 必填格式，Command 的最小格式允许只有正文，更适合快速创建提示词。

### 2. 固定双作用域目录并由项目覆盖全局

全局目录通过 `os.homedir()` 解析为 `~/.yunForce/command`；项目目录使用第一个工作区根目录下的 `.yunForce/command`。加载器分别保留 `global` / `project` 来源快照，运行时注册表按名称合并，同名时项目项覆盖全局项。设置页仍展示两个物理作用域中的文件，因此被覆盖的全局项可见且可编辑。

固定目录减少配置面并与需求保持一致；第一个工作区根目录沿用现有 Skill 安装目标的工作区选择规则。没有打开工作区时禁用项目作用域写操作并展示原因，全局作用域仍可使用。

### 3. 新增独立 Command 模块和宿主侧注册表

新增 `src/command/`，包含类型、Markdown 解析/加载、注册表及 CRUD 存储服务。注册表向斜杠菜单提供合并后的轻量元数据，存储服务负责名称校验、目录内路径解析、原子式写入和删除，并在成功后统一触发重载。所有入口、跳过、覆盖、成功与失败步骤通过 `src/logger.ts` 记录作用域、名称和路径，不记录正文。

不把 Command 塞入 `SkillRegistry`：二者文件约束、设置操作和发送展开语义不同，分离可以避免继续依赖当前 `skill.*` ID 前缀来猜测类型。

### 4. 扩展斜杠候选的显式类型

为候选增加显式 `kind: 'basic' | 'command' | 'agent' | 'skill'`，组装顺序为“基础功能”“命令”“子智能体”“SKILL”。选择 `command` 时移除当前斜杠 token、生成 Command chip、保持文本框聚焦且不发送；每条消息最多引用一个 Command，重新选择时替换旧引用。Skill 的现有多选行为保持不变。

显式类型替代通过 `id` 前缀判断，可让 Webview 稳定区分 Command 与 Skill，并避免把不同语义重新合并到“SKILL与命令”分组。

### 5. 宿主在发送时解析并展开 Command

Webview 的发送消息只携带 Command 名称/作用域标识与用户补充文本，不携带可信正文。Host 在发送时从最新注册表解析有效 Command；若命令已不存在则拒绝本次发送并返回有界中文错误。有效输入按以下结构组装后进入既有会话链路：

```text
[Command: <name>]
<command body>

[用户补充说明]
<user text>
```

补充文本为空时省略对应区块。这样既保留模板边界，又不会引入首版不需要的占位符替换。引用文件上下文继续沿用现有前置逻辑；Command 展开块位于文件上下文之后、Skill 引用与用户补充说明之前。用户可见消息仍展示 Command chip/名称与原始补充说明，避免把较长模板全文塞进输入框。

### 6. 设置页采用作用域标签与主从编辑视图

设置导航在 Skill 后新增“命令”。内容区提供“全局/项目”标签、说明与实际目录路径、刷新按钮、创建按钮、命令列表/空状态，以及同页创建/编辑表单（名称、描述、正文）和删除确认。Host 协议采用请求快照与 create/update/delete/refresh 操作消息；每次成功变更返回最新双作用域快照，并刷新聊天斜杠菜单。

视觉上复用现有设置页 token、卡片、按钮和反馈组件，只借鉴截图的信息层级，不复制外部产品样式。

## Risks / Trade-offs

- [外部编辑不会实时出现] → 设置页和聊天菜单提供刷新，插件激活与 CRUD 成功后自动重载；文件监听留待后续需求。
- [同名覆盖可能让用户误判生效来源] → 列表标出作用域与“被项目覆盖”状态，斜杠菜单描述显示当前生效来源。
- [Markdown frontmatter 解析能力有限] → 仅支持可选的单行 `description`，复用/抽取现有简单解析模式并对格式异常记录中文日志。
- [Command 正文可能包含恶意提示] → 将其视为用户本地内容，仅作为模型文本输入，不执行代码、不加载工作区外路径、不在日志中输出正文。
- [多根工作区只使用首个根目录] → UI 明示实际项目目录，与现有 Skill 安装规则保持一致；多根选择不纳入首版。
- [删除或改名与已选 chip 竞态] → 发送时由 Host 重新解析，缺失时不创建用户消息并提示重新选择。

## Migration Plan

1. 增加 Command 模块、协议和测试，不影响目录不存在时的现有行为。
2. 在扩展激活时装配注册表；不存在的目录按空列表处理，首次创建时再建立目录。
3. 接入设置页 CRUD 与斜杠菜单引用、展开链路，并运行相关测试及 `npm run compile`。
4. 回滚时移除新增装配和 UI；用户创建的 `.yunForce/command` Markdown 文件保留且不会影响旧版本插件。

## Open Questions

- 无阻塞问题。首版明确采用单 Command 引用、无参数插值、手动刷新外部变更；如后续需要 `$ARGUMENTS` 等模板变量，应另立变更扩展文件契约。
