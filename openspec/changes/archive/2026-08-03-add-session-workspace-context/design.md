## Context

当前面板在首次加载 Agent 后创建会话；用户随后选择另一个 Agent 时，`selectedAgentId` 会更新，但当前云端 `session_id` 不变。创建会话的 HTTP 请求只包含 `agent_id` 与可选 `local_tools`，扩展也尚未将 VS Code 工作区根目录传递给云端。

## Goals / Non-Goals

**Goals:**

- 当用户实际切换到不同 Agent 时，创建新会话并在成功后切换 UI 到该会话。
- 在每次会话创建时，将第一个工作区文件夹的文件系统路径作为可选 `workspace_root` 上报。
- 明确云端 API 对字段的校验、存储和使用边界。

**Non-Goals:**

- 不迁移或删除旧会话。
- 不在本次变更中支持多根工作区或同步整个文件树。
- 不授权云端直接访问本地路径；路径只作为会话上下文。

## Decisions

### 以 Agent 标识变化作为模型切换判定

配置 API 将模型附属于 Agent，客户端没有独立模型选择器。因此仅当新选择的 `agent_id` 与当前 `selectedAgentId` 不同时触发创建会话；重复选择同一 Agent 保留当前会话。相比每次点击都创建会话，这能避免无意义地丢弃上下文。

### 使用 `workspace_root` 作为可选、扁平的请求字段

`AIClient.createSession` 接受可选工作区根目录，序列化为 `workspace_root`，与现有 `agent_id`、`local_tools` 保持 snake_case 一致。根目录从 `vscode.workspace.workspaceFolders?.[0]?.uri.fsPath` 取得；无工作区时省略该字段，以保持单文件窗口和旧云端的兼容性。多根工作区暂以上述第一个根目录作为“当前工作区根目录”。

### 会话创建成功后再提交本地 UI 状态

选择新 Agent 时先禁用发送并发出创建请求；只在请求成功后更新 `_currentSessionId` 并发送 `sessionCreated`。失败时保留旧会话和可用输入状态，同时向用户显示错误，避免 UI 指向不存在的会话。

### 云端保存根目录为会话元数据

云端服务接收 `workspace_root` 后将其与创建出的 session 关联，供系统提示、相对路径解释或审计使用。该值不得被解释为云端文件系统可访问路径，也不得用于在服务端执行本地命令。

## Risks / Trade-offs

- [绝对路径可能包含用户目录信息] → 仅在创建会话时传输，并由服务端按会话数据保护策略存储和日志脱敏。
- [选择操作期间创建失败] → 不覆盖旧会话，恢复原输入可用状态并展示创建错误。
- [多根工作区的首根目录不代表用户焦点] → 本期明确首根策略；未来如需支持多根，新增 `workspace_roots` 而不改变现有字段语义。
- [旧云端尚不识别字段] → 字段为可选；部署云端接收逻辑后再启用该字段的业务使用。

## Migration Plan

1. 云端先发布对可选 `workspace_root` 的容忍接收、持久化和安全使用。
2. 发布扩展端，将根目录随新会话上报并在 Agent 切换时创建会话。
3. 监控创建会话失败率与缺失根目录比例；若需要回滚，扩展停止发送该可选字段并恢复原有创建触发点。

## Open Questions

无。本提案采用第一个工作区文件夹作为当前工作区根目录。
