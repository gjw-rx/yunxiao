## Why

现有审批只按工具名在会话内或全局配置中记忆，无法限制到具体工作区、资源路径或有效期；一次宽泛的“始终允许”会扩大后续本地工具调用的权限。`code.edit` 虽已在审批前后检查内容变化，但缺少可随读取结果传递和审计的稳定文件版本契约。

现在需要把两项能力收敛成可验证的本地安全边界，满足恢复型运行中最小授权和过期编辑拒绝的要求。

## What Changes

- 用具备工作区、工具名、规范化资源模式和过期时间的范围授权记录，替代只含工具名的全局允许列表。
- 在审批请求中携带目标资源；仅完全匹配且未过期的范围授权可跳过提示。
- 保持“本次允许”仅限当前会话，并将“始终允许”保存为当前工作区的有限范围授权。
- 为 `code.edit` 明确文件版本从读取、diff 预览到审批后最终写入的连续传递；版本不一致时返回不可重试的冲突且不写入文件。

## Capabilities

### New Capabilities

- `scoped-approval`: 按工作区、工具、资源模式和有效期约束本地工具的审批授权。

### Modified Capabilities

- `approval-gateway`: 将审批记忆从工具级允许列表改为可验证的范围授权。
- `code-edit`: 明确可传递的预览基线版本和审批后版本复核行为。

## Impact

- 修改 `src/core/approvalGateway.ts`、本地工具路由及 VS Code 配置迁移逻辑。
- 修改 `src/tools/code/editFile.ts` 的版本元数据与冲突返回，并补充单元测试。
- 现有 `yunxiaoAgent.alwaysAllowTools` 配置将向后兼容读取，并在首次写入范围授权时迁移。
