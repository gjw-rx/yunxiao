## Context

Phase 1-5 已形成“云端决策、本地执行”的混合编排：云端通过 SSE 发出 `tool_call`，插件执行后通过 `/api/agent/invoke/tool_result` 续流。现有安全检查、超时、重试和输出限制分布在不同工具中，且云端主要依赖日志观察结果大小；Phase 6 需要在不更换传输协议的前提下建立统一边界。

## Goals / Non-Goals

**Goals:**

- 在本地工具执行前后提供统一安全审计和结果治理。
- 让取消、超时、网络重试、并发冲突和工具失败具有一致的生命周期和用户提示。
- 保持 `tool_call`、`/tool_result`、`local_tools` 的向后兼容，并让云端能消费裁剪/脱敏后的结果。
- 为云端补充续流幂等、取消语义、并发结果关联、会话级上下文预算和系统提示约束。

**Non-Goals:**

- 不把本地文件、Shell 或 Git 执行迁移到云端。
- 不在 Phase 6 引入 WebSocket 或批量 `tool_call_batch` 作为必需协议。
- 不改变既有工具名称和权限级别，不实现跨设备分布式锁。

## Decisions

### 1. 本地安全边界权威，云端只消费结果

`securityAudit` 在路由到具体工具前执行路径、命令、敏感资源和并发版本检查；云端不重复执行本地安全判断，只记录审计字段并根据 `ToolMessage` 继续推理。这样避免把工作区安全边界暴露给云端，同时保留云端可观测性。

备选方案是云端先审批准入，但云端无法可靠解析本地路径和工作区状态，因此不采用。

### 2. 统一结果治理放在本地，并在云端做会话级二次预算检查

本地 `BaseTool` 出口统一执行二进制跳过、长度裁剪和秘密脱敏，结果 metadata 标记 `truncated`/`redacted`。云端在注入 `ToolMessage` 前执行仅基于字符/token 预算的二次裁剪并记录日志；已裁剪结果不再重试获取原文。这样既减少敏感数据出端，也防止多轮结果累积撑爆上下文。

### 3. 取消和超时使用现有 `cancelled`/`error` 状态

用户取消、危险命令拦截和审批拒绝使用 `cancelled`；超时、网络或工具执行失败使用 `error`，并在 metadata 中携带可选 `retryable`。云端将两者都注入匹配 `tool_call_id` 的 `ToolMessage`，但对 `cancelled` 不自动重试，对可重试 `error` 最多按请求幂等策略恢复一次。

### 4. 以 call_id 和 session_id 实现幂等与并发关联

云端 `/tool_result` 对 `(session_id, call_id)` 去重：重复提交返回已有续流结果或明确的幂等响应，不重复注入 ToolMessage。并行调用仅在本地工具 schema 声明 `canParallel=true` 且会话无冲突时启用；Phase 6 默认仍按序执行，保证协议兼容。

## Risks / Trade-offs

- [结果裁剪隐藏关键上下文] → 返回裁剪标记、保留尾部/错误区域，并在系统提示中要求 Agent 根据标记改用分页或定向查询。
- [重试导致重复副作用] → 仅对连接建立前失败或明确 `retryable=true` 的结果恢复；写入、提交等操作以 `call_id` 幂等为前提，不由云端盲目重放。
- [脱敏正则误报] → 默认只替换高置信度 key/value 模式，记录 `redacted` 标记；保留本地可见原始结果，不回传原文。
- [云端与本地超时不一致] → 本地超时是执行权威，云端续流端点使用足够的请求空闲窗口，并以结果状态结束会话。

## Migration Plan

1. 先部署云端兼容逻辑：接受已有结果格式，新增 metadata 字段可选，支持幂等和 `cancelled`/`error` 语义。
2. 再发布本地统一安全审计与结果治理；旧云端仍可按原 `ToolMessage` 逻辑运行。
3. 联调通过后启用云端会话级预算和系统提示增强，观察裁剪、重试、取消指标。
4. 回滚时关闭本地并行和云端二次裁剪，保留已有单次工具调用和基础本地限制。

## Open Questions

- 云端实际 LLM 的 token 计数器是否可复用；若不可用，先使用字符预算并记录估算值。
- 是否需要在后续阶段把 `tool_call_batch` 正式纳入公共协议；Phase 6 不依赖该能力。
